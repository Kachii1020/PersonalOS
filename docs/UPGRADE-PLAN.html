코딩 규칙 (CLAUDE.md에서 발췌)

  1. 외부 API는 리포지토리 레이어 뒤에. 컴포넌트가 tsdav, yahoo-finance2, Notion SDK를 직접 import하면 반려. 전부 lib/repos/*.ts를 통한다.
  2. AI 호출 지점은 lib/ai/client.ts 하나뿐. 새 purpose를 추가하려면 SPEC 5.5 표를 먼저 개정한다. 현재 5개: briefing, quiz, material_summary, domain_lesson, weekly_review. 자연어 인터페이스를 추가하면 6번째가 된다 — SPEC 개정 필요.
  3. 실패는 조용하지 않다. catch {} 빈 블록 금지. 모든 외부 호출 실패는 sync_state 또는 job_runs에 기록.
  4. 글래스는 달력·브리핑 카드에만. 나머지는 불투명 --surface.
  5. 숫자는 등폭 + 우측 정렬. .num 클래스 사용.
  6. 모든 작업 후 npm run typecheck && npm run lint && npm run test.
  7. 마이그레이션은 기존 파일 수정 금지. 새 파일로 alter.

이건 선택적이다. 스트릭 + 퀵 캡처 + 커맨드 팔레트만으로도 Tier 1의 목적(매일 여는 이유)은 충분히 달성된다. 실사용 1주일(0-C) 후에 필요성을 판단해도 늦지 않다.

마이그레이션 전체

Tier 1–3 전체에서 필요한 스키마 변경은 마이그레이션 1개로 묶는다.

-- supabase/migrations/0011_upgrade_streaks_prefs.sql

-- 1. 알림 세분화 (Tier 2-C)
alter table push_subscriptions
  add column if not exists prefs jsonb
    not null default '{"briefing":true,"quiz":true,"deadline":true,"sync_fail":false}'::jsonb;

-- 2. 스트릭 조회용 뷰는 만들지 않는다.
--    단일 사용자라 집계가 빠르고, 뷰를 만들면 마이그레이션이 복잡해진다.
--    lib/repos/streaks.ts가 직접 쿼리한다.

-- 3. 검색 인덱스 (Tier 1-C) — 데이터가 작아서 ilike로 충분하지만,
--    events.summary와 tasks.title에 trigram 인덱스를 미리 걸어둔다.
create extension if not exists pg_trgm;
create index if not exists idx_events_summary_trgm on events using gin (summary gin_trgm_ops);
create index if not exists idx_tasks_title_trgm on tasks using gin (title gin_trgm_ops);

-- GRANT (0001 패턴 따름)
grant all on push_subscriptions to service_role;
grant select, insert, update, delete on push_subscriptions to authenticated;
